## 🔍 アーカイブドキュメントの使用方法

### 参照が推奨されるケース
- 過去の設計判断の背景を理解したい
- 歴史的な経緯を調査したい
- 移行前のアーキテクチャを確認したい

### 参照が非推奨のケース
- 現在の実装方法を知りたい → 最新ドキュメントを参照
- 新機能を開発したい → 最新ドキュメントを参照
- トラブルシューティングをしたい → 最新ドキュメントを参照

## 📜 アーカイブポリシー

### アーカイブ対象
以下の条件に該当するドキュメントをアーカイブします:

1. **実装との乖離**: 現在のコードベースと内容が大きく異なる
2. **役割の終了**: 移行計画など、完了したプロジェクトのドキュメント
3. **重複**: 新しいドキュメントで同じ内容がカバーされている
4. **古いバージョン**: 大規模な更新により前バージョンが不要になった

### アーカイブプロセス
1. アーカイブ対象のドキュメントを特定
2. 代替ドキュメントを作成（必要な場合）
3. `_archive/YYYY-description/` ディレクトリに移動
4. このREADME.mdにエントリを追加
5. PRで変更をレビュー

### 保持期間
- **最低保持期間**: 1年
- **最大保持期間**: 制限なし（ディスク容量が許す限り）
- **削除判断**: プロジェクトリード判断

## 🔄 アーカイブからの復元

アーカイブされたドキュメントを復元する必要がある場合:

```bash
# 1. アーカイブから親ディレクトリにコピー
cp docs/_archive/2024-legacy/DOCUMENT_NAME.md docs/

# 2. 内容を最新の実装に合わせて更新
vim docs/DOCUMENT_NAME.md

# 3. PRを作成してレビュー依頼
```
